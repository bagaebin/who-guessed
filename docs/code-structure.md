# 코드 구조 및 런타임 아키텍처

이 문서는 현재 클라이언트 코드베이스의 레이아웃, 런타임 흐름, 연동 지점을 평가합니다. React + Three.js 앱이 어떻게 구성되고 상태와 렌더링이 조정되는지를 설명하여 게임플레이/애니메이션 스펙을 보완합니다.

## 상위 레이아웃
- **엔트리 및 합성**: `src/main.tsx`가 `App`을 마운트하며, 3D 보드(`Board3D`), 관리자/UI 패널(`UiPanel`), 로고 오버레이를 한 화면에 엮어 보여줍니다.
- **상태 컨테이너**: `src/state/gameStore.ts`의 단일 Zustand 스토어가 모든 게임 데이터(타일, 페이즈, 질문, 생성 큐, 제거 결과, UI 락)를 보유하고 텍스트 제출/리셋/수정 액션을 노출합니다.
- **3D 씬 레이어**: `@react-three/fiber` + Drei로 보드를 렌더하는 컴포넌트가 `src/components`에 있습니다. `Board3D`가 카메라 위치와 인트로 드롭을 설정하고, `TileCard`가 개별 타일을, `PlayerCameraTile`이 플레이어 마커를 배치합니다.
- **UX/관리 레이어**: `UiPanel`이 컨트롤 패널 및 진단 콘솔 역할을 하며, 스토어 상태를 읽고 답변 제출, 게임 리셋, 추론 보기, 생성 로그 확인을 위한 디스패처를 호출합니다.
- **보조 모듈**: `src/api`의 API 클라이언트가 이미지 생성/분석, LLM 제거 엔드포인트(또는 목)를 감싸고, `src/utils`는 페이즈 계산, 제거 결과 정규화, 타일 스타일 헬퍼를 제공합니다. 정적 시드/질문은 `src/data`, 타입 계약은 `src/types`에 있습니다.

## 렌더링 및 상호작용 흐름
- `App`은 스토어에서 필터된 타일과 활성 질문을 가져오고, `Alt`로 관리자 패널 토글, `react-spring` 기반 로고 페이드 및 인트로 오디오 재생을 처리합니다.
- `Board3D`는 고정된 5열 그리드와 계단식 오프셋, 카메라 타깃/위치를 계산하고 최대 24개 타일의 인트로 드롭 시퀀스를 관리합니다. props 변경 시 Three.js 카메라를 갱신하고 조명/그림자/플레이어 마커/타일 그리드를 캔버스에 배치합니다.
- `UiPanel`은 텍스트에어리어를 스토어 상태와 바인딩하고, 생성·제거 진행 시 제출을 잠그며, 현재 페이즈 힌트와 최신 제거 요약/추론/생성 콘솔 스냅샷을 표시합니다.

## 게임 상태 라이프사이클
- **초기화**: `gameStore`는 10개의 플레이스홀더 타일(`buildInitialTiles`)을 준비하고 초기 랜덤 질문을 뽑은 뒤, 생성 진행 없음 상태로 `phase`를 `gen1`에 설정합니다.
- **생성 단계**: 생성 페이즈 동안 사용자가 텍스트를 제출하면 스토어는 `PendingGenerationJob`을 큐에 넣고 입력을 잠근 뒤, 생성 카운터를 증가시키고 다음 질문을 예약하며 큐를 처리합니다. 각 작업은 프롬프트를 만들고 체인별 이미지를 가져와 외형 핵심을 분석하고, 해당 타일을 갱신하고, 로그를 기록하며, 페이즈별 가시성을 진전시키고, 10-슬롯 파이프라인을 유지합니다. 질문은 3초 잠금 이후 자동 회전하여 프롬프트 중첩을 방지합니다.
- **제거 단계**: 10개 슬롯 생성 완료 후 제출은 제거 로직으로 전환됩니다. 스토어가 `inferPlayerAppearance`를 호출해 예상 제거 대상을 받고, 페이즈 범위에 맞게 정규화한 뒤 타일을 뒤집고, 남은 가시 타일 수에 따라 `phase`를 업데이트합니다. 라운드 카운터와 상태 메시지가 최종 공개까지의 진행 상황을 반영합니다.
- **리셋 및 가시성**: `reset`이 타이머/카운터/로그/상태를 초기화하고 타일과 첫 질문을 재적재합니다. 각 타일의 가시성은 현재 페이즈에 따라 `updateVisibility`로 재계산되어 잠금 해제 전까지 숨김을 유지합니다.

## 네트워킹 및 폴백
- **이미지 생성**: `requestImages`는 `VITE_IMAGE_ENDPOINT`를 호출하며, 응답이 없거나 실패하면 단계/슬롯 정보가 표시된 base64 SVG 플레이스홀더를 사용합니다.
- **이미지 분석**: `analyzeGeneratedImages`는 `VITE_IMAGE_ANALYSIS_ENDPOINT`로 생성 이미지를 분석해 외형 핵심을 구합니다. 응답이 없으면 기본 시드와 프롬프트 해싱을 활용한 리믹스 코어를 반환합니다.
- **LLM 제거**: `inferPlayerAppearance`는 플레이어 텍스트와 남은 타일을 `VITE_LLM_ENDPOINT`로 전송합니다. 없거나 무효한 경우 페이즈별 범위를 사용해 제거 대상을 샘플링하고, 시드 타일 프로필과 목업 추론을 에코하여 오프라인에서도 진행이 가능하게 합니다.

## 주요 관례
- **페이즈 계산**: 생성 페이즈는 `GENERATION_PHASES`에 열거되며, 제거 페이즈(`early`, `mid`, `late`)는 남은 타일 수와 임계값/제거 범위를 기반으로 파생됩니다.
- **타일 식별자와 체인**: 10개의 체인 ID(`chain-1`…`chain-10`)가 보드 슬롯에 고정 매핑됩니다. 가시성 세트는 생성 페이즈별로 미리 계산되어 이미지가 생성되면 순차적으로 드러납니다.
- **프롬프트와 해싱**: 프롬프트 텍스트는 현재 질문/답변을 삽입하며, 결정적 리믹스(질문 + 슬롯 솔트 해싱)로 분석 데이터 부재 시에도 시드 속성을 변주해 균질화를 방지합니다.
- **로깅 및 기록**: 생성 로그는 단계, 프롬프트, 질문/답변, 출력, 타임스탬프를 담아 관리자 검토가 가능하게 합니다. 플레이어 입력 기록은 페이즈 전환 동안 유지되어 감사 및 질문 회전 추적에 사용됩니다.

## 관찰 및 잠재 리스크
- `App`의 오디오 재생은 자동 실행에 의존하므로 클릭/키다운 폴백이 있어도 브라우저에서 차단될 수 있습니다.
- 생성 큐는 재귀적으로 한 번에 하나씩 처리하므로 엔드포인트가 지연·실패하면 재시도/백오프 없이 큐가 지연될 수 있습니다.
- `requestImages`, `analyzeGeneratedImages`는 슬롯 순서가 결정적이라고 가정하므로 백엔드 응답 형태가 바뀌면 추가 검증이 필요합니다.
- 가시성 로직은 미생성 타일을 플레이스홀더로 대체해 숨기며, 페이즈가 설정 가능하게 바뀔 경우 `visibilityByPhase`와 `updateVisibility`의 동기화를 확인해야 합니다.
