# 코드 구조 효율성 및 최적화 평가

본 문서는 현재 클라이언트 코드베이스의 주요 런타임 경로를 기준으로 성능/자원 효율성, 잠재적 최적화 포인트, 유지보수 위험도를 평가한다. 대상은 React/React Three Fiber 기반 UI 계층과 Zustand 상태 관리, 이미지/LLM 연계 흐름이다.

## 렌더링 및 애니메이션
- **3D 보드 배치 계산**: `Board3D`는 5열 고정 그리드와 계단식 높이를 미리 계산하고 `useMemo`로 카메라 타깃/포지션을 캐싱해 불필요한 재계산을 줄인다. 이는 정적인 레이아웃 변화가 많지 않은 구조에 적합하며, 타일 수 변경 시에도 메모이제이션을 통해 리렌더 비용을 억제한다.【F:src/components/Board3D.tsx†L15-L151】
- **인트로 드롭 애니메이션**: 각 타일은 고유 지연값과 초기 높이를 갖고 스프링 애니메이션을 수행하며, 완료 시 카운터를 증가시킨다. `useMemo` 기반 타일 순서 맵과 `useCallback` 완료 핸들러로 불필요한 함수 재생성을 줄이고 있지만, 최대 24개의 타일에 개별 스프링이 붙어 있어 저사양 GPU에서는 초반 프레임 드랍이 발생할 수 있다. 필요 시 `MAX_INTRO_TILE_COUNT` 축소 또는 지연 시간 증가로 부하를 완화할 수 있다.【F:src/components/Board3D.tsx†L26-L185】【F:src/components/TileCard.tsx†L21-L110】
- **애니메이션 로깅 비용**: 로고 페이드 스프링의 `onChange`와 `onRest`에서 매 프레임 콘솔 로그가 출력된다. 렌더 루프 내 콘솔 I/O는 메인 스레드를 블로킹하므로 배포 빌드에서는 로그를 제거하거나 `import.meta.env.DEV` 조건부 로깅으로 전환하는 것이 좋다.【F:src/App.tsx†L29-L43】
- **텍스처 로딩 캐싱**: `useTexture`는 내부 캐시를 제공하지만, 타일 이미지가 자주 교체되는 워크플로라면 `THREE.Cache.enabled = true` 설정 또는 공용 텍스처 매퍼를 도입해 재다운로드를 피할 수 있다. 현재는 개별 타일 단위로 훅을 호출하므로 이미지 URL이 자주 바뀌면 네트워크/디코딩 비용이 누적될 수 있다.【F:src/components/TileCard.tsx†L76-L108】

## 상태 관리 및 비동기 흐름
- **생성 큐 직렬 처리**: `processGenerationQueue`는 `pendingGenerations`를 순차 처리하며, 완료 후 재귀적으로 다음 작업을 이어간다. 직렬 처리로 인퍼런스 부하를 제어하지만, 큐 길이가 길어질 경우 재귀 깊이와 상태 변경 이벤트가 누적될 수 있다. 비동기 루프(`while`/`for await`)로 전환하면 호출 스택을 줄이고 추후 병렬화 옵션을 추가하기 쉽다.【F:src/state/gameStore.ts†L277-L360】
- **질문 로테이션 타이머**: 새 질문 예약 시 기존 타이머를 해제하고 입력을 잠금으로 전환해 경쟁 상태를 줄인다. 다만 `scheduleNextQuestion`가 상태 업데이트 두 번(`set`)을 호출하므로, 불변성 업데이트 비용을 줄이려면 하나의 `set` 블록 내에서 타이머 ID와 락 상태를 함께 처리하는 방안을 고려할 수 있다.【F:src/state/gameStore.ts†L57-L95】
- **세션 오디오 초기화**: 앱 마운트 시 세 개의 `Audio` 인스턴스를 생성하고, 두 번의 인트로가 끝난 뒤 BGM을 재생한다. 이벤트 리스너와 `setTimeout`은 언마운트 시 정리되지만, 사용자의 상호작용마다 `playAudio`가 반복 호출되어 오토플레이 정책 회피를 시도한다. 반복 호출 시 `play()` 실패 로그가 다량 발생할 수 있으므로, 재생 성공 후 리스너 제거 또는 재생 상태 플래그를 더 빠르게 업데이트하는 최적화가 가능하다.【F:src/App.tsx†L61-L133】
- **타일 가시성 업데이트**: 세대 단계별로 미리 계산된 `visibilityByPhase`를 기반으로 가시성을 결정하여 조건 분기 비용을 줄이고, 플레이스홀더 이미지 재지정을 통해 생성되지 않은 슬롯을 명확히 표시한다. 현재 로직은 전체 타일 배열을 매번 매핑하므로, 타일 수가 늘어나면 `Set` 기반 필터링만 업데이트하도록 부분 업데이트 전략을 검토할 수 있다.【F:src/state/gameStore.ts†L97-L220】

## 네트워크 및 백엔드 연동 효율
- **이미지 생성 파이프라인**: 프롬프트를 한 번 구성한 뒤 슬롯별 체인 ID로 요청을 보내고, 분석 결과를 활용해 코어 프로필을 업데이트한다. 단일 질문/답변에 대해 슬롯 하나씩 생성하므로 사용량 제어에는 유리하지만, GPU 파이프라인의 배치 이점을 활용하지 못한다. 동일 질문으로 여러 체인을 생성해야 한다면 `requestImages` 호출을 묶어 병렬 슬롯 생성 후 분석을 한 번에 수행하는 배치 모드를 고려할 수 있다.【F:src/state/gameStore.ts†L229-L358】
- **오류 메시지 가시성**: 엔드포인트 미설정/404 등의 오류를 구체적으로 매핑해 사용자 메시지로 표출한다. 이는 문제 해결 시간을 줄이지만, 반복 오류 시 동일한 메시지를 계속 세팅하며 상태 변경 이벤트를 발생시킨다. 같은 메시지가 연속 세팅되면 상태 라이브러리 수준에서 noop 처리되지만, 로거가 연결되어 있다면 스팸 가능성이 있으므로 최소 변경 감지 후 업데이트하는 방식을 추가할 수 있다.【F:src/state/gameStore.ts†L186-L205】【F:src/state/gameStore.ts†L335-L351】

## 최적화 우선순위 제안
1. **프로덕션 콘솔 로그 제거**: 애니메이션과 초기화 단계의 잦은 로그를 프로덕션 빌드에서 제거해 메인 스레드 부하와 콘솔 스팸을 줄인다.【F:src/App.tsx†L29-L43】【F:src/components/TileCard.tsx†L32-L44】
2. **생성 큐 실행 방식 단순화**: 재귀 기반 큐 처리를 반복 루프 형태로 리팩터링해 호출 스택 성장 위험을 낮추고, 향후 동시 생성/배치 생성 기능 추가를 쉽게 만든다.【F:src/state/gameStore.ts†L277-L360】
3. **텍스처/이미지 캐시 강화**: 타일 이미지 변경이 잦은 세션을 대비해 글로벌 텍스처 캐시를 활성화하고, 이미지 URL이 동일할 때는 재요청을 피하는 메커니즘을 추가한다.【F:src/components/TileCard.tsx†L76-L108】
4. **타이머/상태 업데이트 결합**: 질문 회전 타이머 설정과 입력 잠금을 단일 업데이트로 묶어 상태 변경 횟수를 줄이고, 개발자 실수를 방지한다.【F:src/state/gameStore.ts†L57-L95】
5. **오디오 재생 제어 플래그 강화**: 배경음 재생 성공 시 즉시 상호작용 리스너를 제거하고, 실패 시에도 재시도 횟수를 제한해 로그/CPU 사용을 줄인다.【F:src/App.tsx†L61-L133】
